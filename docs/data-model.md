# Data model v1.1.0

`schemas/catalog.schema.json` declares normalized entity arrays. IDs are globally unique; a human-facing PID is unique case-insensitively. Models belong to a family/manufacturer; exact PIDs reference their model and an approved identity assertion extracted from an ordering table. The property `orderabilityAssertionId` records documented ordering-table identity, not real-time sales availability. Candidates never become matching products implicitly.

Assertions use `subjectId`, a typed `predicate` and value, compatibility state, source, excerpt and section, UTC `verifiedAt`, confidence, interpretation, reviewer/status, conflict/supersession links and a review flag. Source URL/title/date/type are normalized via `sourceId`. Applicability holds exact PID IDs, firmware bounds, license IDs, software version IDs, management mode IDs, architecture, configuration, effective date and asset limit. Null means unspecified, never unrestricted guaranteed support. Free-text prerequisites remain unresolved/conditional in the rules engine.

Port inventories are arrays of role/media/count/rates/origin/module/PoE/combo-group objects. Copper describes the medium; the optional connector field distinguishes RJ45 and M12 interfaces. SFP and SFP+ mean cages/slots, not installed optical transceivers. Fixed fiber is a separate predicate. Combo ports need a shared group. Expansion-origin ports require a module reference and cannot inflate built-in scalar counts. Flexible LAN/WAN interfaces are not dedicated uplinks and cannot be counted twice. Rate selection asks for the fastest available port, not a guarantee for every access port.

License offers and commercial entitlements are distinct from technical compatibility. Entitlements carry offer/feature/quantity/duration plus eligibility and actual-activation caveats. A 36-month included term does not mean permanent entitlement. Source publication/check/verification/material-change dates are separate. Last material change remains null until an actual reviewed claim change is established.

`data/software/` and `data/compatibility/` reserve a future physical split. In v1, software and assertions remain normalized arrays in the single catalog to avoid divergent copies. `data/competitors/battlecards.json` is empty, governed by a future-ready schema for exact SKU/category, sources, condition-specific parity, strengths and weaknesses on both sides, operations model, licensing, independent user evidence, questions and balanced objections. There are no competitor equivalence claims.

## Phase B v1.1.0 additions

The schema adds physical base-port count, temperature ranges with enclosure/airflow conditions, cellular/wireless capability, partial typed lists for protocols/standards/security/OS/PoE, power summaries, documented replacements and software licensing-rule statements. Port connector form factor is optional and distinct from medium (for example M12 copper versus RJ45 copper). A shared combo group counts once. Numeric base counts are independently checked against the inventory.

Applicability can identify feature conjunctions, one-of license requirements, software releases, deployment architecture, and separate commercial order/upgrade thresholds. Scoped negatives need matching context; a CV+SEA conjunction cannot exclude CV alone. Specific approved assertions may supersede earlier records without deleting provenance. Family-to-PID evidence stays derived/conditional. Missing members of a partial list stay unknown.

Future announced lifecycle dates are allowed; impossible dates and future verification/check dates are rejected. Product documentation references are validated. Sources can declare a manufacturer ID whose official domains must match the URL; legacy Cisco sources default only to Cisco domains. This supports future competitor research while preserving host-authority checks.

Review issues retain open/partially-resolved/resolved status and resolution text. Audit history is immutable, path constrained, count checked and linked to existing source/assertion identities. Observation reports never claim unparsed technical or lifecycle changes. New reports include hashes of the semantic dataset and source registry so evidence scope can be traced independently of formatting.
